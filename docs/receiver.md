# 接收页与自托管

默认入口：[扫码桥大文件接收页](https://1CWwW.github.io/scan-bridge/receiver/)。iPhone 推荐 Safari，Android 推荐支持相机与 OPFS 的新版系统浏览器。首次完整加载后，Service Worker 会缓存页面和编解码资源，可在离线状态下重开。文件内容只通过相机接收和本机写盘，程序不上传接收数据，不含统计或第三方脚本。

发送端依旧是离线单文件 HTML。接收端是 `dist/receiver/` 目录，包含网页、两个 Worker、协议和哈希库、WASM 解码器、离线缓存及许可证。相机和浏览器文件系统要求安全上下文，不能承诺手机直接打开 `file://` HTML 即可运行。

## 自托管

将发行包 `scan-bridge-v1.5.1-receiver.zip` 解压后的整个目录部署到静态 HTTPS 服务器，保持文件相对路径，并为 `.wasm` 提供 `application/wasm`。不需要数据库、上传接口、账户或跨源隔离响应头。首次加载的所有资源均来自同一站点。

电脑发送页“自托管接收地址”中填写新的 HTTPS 网址，更新接收二维码即可。每个来源有独立浏览器存储；更换网址来源、清除网站数据或使用另一个浏览器都不会自动带走当前接收进度。请先在原接收页保存文件。

在电脑本机测试可使用 Python 标准库：

```sh
python3 -m http.server 8000 --directory dist
```

本机访问 `http://localhost:8000/receiver/`。手机通过电脑局域网 IP 访问普通 HTTP 通常无法申请相机权限；手机使用应部署有效 HTTPS。

仓库的 `Publish receiver` 工作流会在主分支三平台验证通过后部署 GitHub Pages。自行 Fork 时需要启用仓库 Pages、选择 GitHub Actions，并将发送端默认网址改成自己的站点。

## 存储与恢复

一个接收任务使用浏览器 OPFS 中的 `scan-bridge-recv-v1/`，包含 `payload.bin` 和已提交数据块的小型 JSON 日志。输入的原文件名只作为下载名称，不用于构造本地目录。每块先验证摘要、写入并 flush、回读校验，再提交块日志；异常写入长度不会计为完成。

刷新会复查日志对应的磁盘数据。未提交、撕裂或损坏的块将重新显示为缺失。全部收齐后，完整文件长度和 SHA-256 必须匹配才允许导出。浏览器清理网站数据仍可能删除整个任务；“保留接收进度”只是向浏览器申请持久存储。

电脑 Chrome/Edge 可选择输出文件并流式复制。没有保存选择器的浏览器使用 OPFS 磁盘 File 的下载链接；不创建全文件 ArrayBuffer。系统的最终下载行为、额外磁盘空间需求以及手机多 GB 导出仍需设备实测。确认导出成功后再清除任务。

底层仍采用独立 8 MiB CIMBAR 流，接收器在每个流落盘后重建解码器，释放内存并避免长任务中的上游 7 位编码 ID 回绕干扰。定时循环只有单向传输，没有手机接收确认；漏块按提示重播。

该实现提高的是接收容量和完整文件的使用体验，不增加光学带宽。例如有效速度为 100 KiB/s 时，200 MiB 纯数据约需 34 分钟，2 GiB 约需 5.8 小时，实际还会有冗余、定位和重扫开销。

## 当前数据块进度慢时

先保持同一块，不要在未收齐时定时切走。90 MiB 文件会有 12 个数据块，默认每个 8 MiB；当前块条表示喷泉码解码器的估计进度，整文件条只累计已校验并写盘的原始字节，二者不同。5 FPS 表示电脑每秒仅输出约 5 张新画面，不是手机每秒能有效接收的保证。

先全屏显示电脑彩色码，保留四角、保持对焦、避免反光和抖动。若画面清晰，尝试从 5 FPS 提到 10 FPS；有码帧比例明显下降则退回 5 FPS。不要在未观察效果时直接使用最高帧率。云桌面画面如果经过缩放或压缩，也可能影响小格子和颜色的可辨认程度，需要在实际显示环境测试。

v1.5.1 接收页显示最近三秒的处理帧率、有码帧比例、平均解码耗时及实际处理尺寸。有码帧是指解出至少一些有效编码数据的画面，重复画面也可能计入，因此该比例不等于文件净吞吐量。低比例优先检查画面清晰度和取景；高解码耗时说明手机处理能力也在限制速度。这些诊断仅在本机计算。

新版按视频新帧通知采集，解码器忙时只保留“有更新画面”的标记，空闲后取最新画面，不排队堆积图片。旧浏览器回退为 33 毫秒检查，并仍限制只有一帧在处理。视频尺寸没变时不重建画布缓冲。偶尔提取失败会保留上次已知的块进度；切换解码器时才重置。不会用计时动画虚构接收进度，也不承诺固定提速倍数。

视频新帧接口见 [MDN requestVideoFrameCallback](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)；独立有效图像与喷泉码恢复的关系见 [libcimbar v0.6.8](https://github.com/sz3/libcimbar/tree/v0.6.8)。
