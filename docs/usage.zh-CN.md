# 扫码桥 v1.5 使用说明

这是一个可在电脑浏览器中离线打开的文本与文件传输工具。面向办公、学习、开发等场景，不要求安装 Office 或手机与电脑连接同一网络。

## 打开工具

下载 `scan-bridge.html`，在 Windows、macOS、Linux 上双击，用现代浏览器打开。电脑无需联网。若系统没有关联 HTML，可在文件管理器中选择“打开方式”。

## 普通文本：扫码直接复制

1. 默认选择“直接文本二维码”。粘贴文字、会议记录、网址、代码等内容。
2. 点击“生成文本二维码”，用支持纯文本的手机扫码工具扫描，读取并复制原文。
3. 长文本分成多张，按顺序扫描、复制、拼接，不额外插入空格或换行。

每张可选 600 / 1200 / 2200 个 UTF-8 字节。中文通常占 3 字节，常见表情占 4 字节。二维码只含对应原文，不含页码或链接；顺序显示在电脑上。识别困难时试 600 字节。

系统相机可能只显示网址而不支持完整复制文本，需换用文本扫码工具。二维码内容已由独立解码器核对；扫码工具仍可能改变复制格式。文本框使用浏览器的换行格式；保留文件原本的 CRLF / LF 字节时请传原文件。大量文字需要自动恢复时，切换文件模式发送文本文件。“保存二维码”是可选的 PNG 导出。

## 文件：保持原格式和内容

1. 切换“文件传输”，拖入文件或文件夹，或用“选择文件”“选择文件夹”。
2. 默认“自动：单文件直传，多文件打包”。点击“准备发送”。
3. 手机扫描右侧小二维码，在浏览器打开接收页并允许相机访问，点击“开启相机”（已固定 B 模式）。
4. 电脑点击“开始传输”。手机对准完整彩色码及四角标记，等待接收完成。
5. 保存原文件；收到 ZIP 时先解压。电脑点击“停止”。

Word、Excel、PPT、WPS、PDF、图片、ZIP、音视频、源码等均按原始字节读取，不限制扩展名，也不转换文档格式。手机显示或编辑文件需要对应应用。

单个独立文件默认直接发送。多个文件、文件夹（保留目录）、附带说明或摘要、空文件会打包。小批量使用 ZIP，超过 64 MiB 自动改为流式 TAR；也可手动选择 TAR。大批量若必须为 ZIP，请先用系统压缩工具打包，再拖入此工具分卷。单个已经存在的 ZIP 直接作为原文件传输。

## 手机接收方式

在“手机系统”中选择设备，可查看对应提示：

- **iPhone / iPad**：Safari 打开接收页并允许相机，完成后分享到“文件”App，ZIP 点击解压。
- **Android**：支持相机的浏览器打开接收页，或选择上游 CFC 接收应用。应用安装后可离线接收；上游目前正式支持 arm64-v8a。文件保存到下载目录或文件管理工具。
- **HarmonyOS / 其他系统**：使用支持相机的系统浏览器，先用小文件验证兼容性，不把 Android APK 的支持范围直接等同于这些系统。
- **不确定系统**：选择通用提示。扫码后若打开应用内网页，使用菜单改为在系统浏览器打开。

新版网页接收端为 [扫码桥接收页](https://1CWwW.github.io/scan-bridge/receiver/)，Android 应用来自 [上游 CFC](https://github.com/sz3/cfc/releases)。手机首次加载网页需要联网，电脑发送端可以离线。文件通过屏幕与相机传递。

新版接收页需要 HTTPS / localhost、相机权限、OPFS、后台同步写盘和 Web Locks。页面会检查实际可用能力，不支持时显示原因，不会退回全文件内存拼接。多 GB 接收和导出仍需手机实测，请退出无痕模式并留出充足空间。“保留接收进度”会请求浏览器持久存储，授权结果由浏览器决定，清除网站数据仍会删除进度。

旧 CFC / CIMBAR 接收器不会自动合并扫码桥数据块；使用它们时仍需逐卷保存，再使用独立还原工具。

## 可选设置

- **附带文字说明**：展开文件模式输入框，填写说明或粘贴长文本。ZIP 内保存为 `__scanbridge__/pasted-text.txt`，不改动原文件。
- **文本内容摘要**：默认关闭。开启后增加 `__scanbridge__/text-summary.md`，展示 UTF-8 文本文件内容。它不提取 Office / PDF 的内部文字，二进制与非 UTF-8 文件仍按原字节保留。
- **开发目录过滤**：默认关闭。传源码时可开启，忽略 `.git`、`target`、`build`、`out`、`node_modules`、`.gradle`、`.idea` 等目录。普通办公文件夹无需开启。
- **校验清单**：新生成的 ZIP / TAR 含 `__scanbridge__/manifest.json`，记录原文件路径、字节数及 SHA-256。此根目录是程序保留名称。

## 容量与故障排查

已取消文件总量 20 MiB 和 ZIP 25 MiB 的限制，支持超过 2 GiB 的单文件和大批量 TAR；每批最多 5000 个原文件。超过 8 MiB 自动切为 8 MiB 数据块，新接收页自动写盘并最终保存一个完整文件，无需逐卷下载和手动还原。可手动切块或定时循环，缺块按提示补扫；刷新会重新校验并恢复已写入进度，见 [大文件说明](large-files.md)。

大型 TAR 请关闭可选文本摘要；原文件及逐文件校验清单会完整保留。内存 ZIP 模式仅处理 64 MiB 以内原始内容，大批量使用 TAR 或预先制作 ZIP。已压缩文档、图片、视频通常难以再次缩小。扫码传几 GB 可能需要数小时乃至更久，不承诺固定速率。

文件夹拖入被浏览器限制时改用“选择文件夹”，或先压缩为 ZIP 再拖入。无需特殊浏览器启动参数。引擎无法启动时确认现代浏览器的 JavaScript 与图形加速可用。

扫描慢时先全屏、对焦并调整亮度和距离；5 FPS 能稳定识别后，可尝试 10 FPS。接收页显示处理帧率、有码帧比例和解码耗时，详见 [扫描诊断](receiver.md#当前数据块进度慢时)。彩色动画会快速闪动，对闪光敏感的人请避免直视。

电脑没有手机反馈通道，以手机完成进度为准。修改文本、文件或打包选项会清除旧结果，需重新准备。真实手机链路仍需实机测试，验证范围见 [兼容性说明](compatibility.md)。
